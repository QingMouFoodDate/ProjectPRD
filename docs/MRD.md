## 1. 市场分析 (Market Analysis)

### 1.1 场景与现状

**场景**: 食品包装上的生产日期是印刷/喷码的，字体点阵化、位置随 SKU 漂移、常与保质期和批号混排。
人工核对效率低且易错，客户与仓管都有自动化诉求。

**技术现状**: 这类"小目标文本区域检测 + 识别"任务在技术上已经成熟，难点**不在模型本身**，
而在数据：**没有现成数据集，必须自己采、自己标、自己迭代**。

**平台现状**: 数据采集、标注、训练、部署是四个割裂的环节，每个团队都在重复造同一套工具链。

### 1.2 竞争壁垒分析

| 壁垒类型 | 说明 |
| :--- | :--- |
| **数据壁垒** | 真正的护城河。覆盖 SKU 数量、光照/角度多样性、喷码样式的数据积累，无法靠采购获得。 |
| **工程壁垒** | 低。训练一个检测模型本身不难；难的是让整条链路可持续、可追溯、可复现。 |
| **模型壁垒** | 低。开源检测框架众多，模型结构不是差异化来源。 |
| **场景壁垒** | 中。日期场景的特殊性（点阵字体、曲面变形、格式归一、日期/保质期混淆）需要领域定制的清洗与后处理。 |

**结论**: 本项目的价值集中在**数据资产积累**与**迭代效率**，而非模型创新。因此基建必须为"长期反复迭代"服务。

### 1.3 为什么自建而非采购

三类替代方案的代价（2026 年公开定价）：

| 方案 | 数据位置 | 费用 | 对本场景的适配度 |
| :--- | :--- | :--- | :--- |
| **Roboflow** | 云端 | Free 10 credits/月；Core **$39/月**；Enterprise 询价 | 标注与训练链路完整，但数据出本机，且无法承载采集作业链 |
| **Ultralytics Platform** | 云端 | Free（100GB / 3 并发训练）；Pro **$29/座位/月 + $30 credits**；GPU **$0.24–7.39/小时** | 体验最好，但**代码与模型均为 AGPL-3.0**，内部私有使用亦需 Enterprise 授权 |
| **Label Studio + 自研脚本** | 本机 | Community 自托管**免费**；Starter Cloud **$99/月**（≤12 用户）+ $49/额外用户 | 标注能力成熟，但训练调度、版本、血缘全要自研，等于只解决 1/4 问题 |

**结论**: 没有单一现成产品同时满足「数据不出本机 + 采集作业链 + 训练可追溯 + 无授权负担」。
自建的成本是一次性的研发投入，收益是**边际成本为零**的长期迭代能力。

## 2. 用户分析 (Target Audience & Personas)

### 2.1 核心客群

**唯一客群**: 本项目团队自身（2~3 人）。这是一个**内部基建**，不对外提供，不做多租户。
但设计上需覆盖三类使用角色。

### 2.2 用户画像 (Personas)

#### Persona A: "Trainer" 阿舟（训练者 / 主要使用者）

*   **身份**: 负责模型效果的研发。日常动作是"看指标 → 调参 → 补数据 → 重训"。
*   **痛点**:
    *   "上次那个 mAP 0.87 的模型，我记不清用的是哪批数据、哪组超参。"
    *   "切分做错了，验证集里有和训练集同一个视频的相邻帧，mAP 虚高，上线就崩。"
    *   "补了 500 张标好的图，不知道怎么快速重训一版对比效果。"
*   **核心诉求**: **可复现**。同样的数据 + 同样的配置，必须产出同样的结果；每次实验都能对比。
*   **衡量**: 一次「补数据 → 训练 → 对比」的耗时。

#### Persona B: "Annotator" 小林（标注员）

*   **身份**: 负责画框。可能是在校兼职或团队成员轮流兼任。
*   **痛点**:
    *   "标到一半不知道自己标了多少、还剩多少。"
    *   "同一张图要求改标注，前后的框对不上，只能全部重画。"
    *   "全是纯手工画框，慢且枯燥，容易漏标。"
*   **核心诉求**: **顺手**。快捷键齐全、自动保存、能批量传播、有 AI 预标注辅助。
*   **衡量**: 单张图的平均标注耗时与返工率。

#### Persona C: "Consumer" 末端用户（未来的小程序 / App 用户）

*   **身份**: 消费者（买东西前想看新鲜度）或仓管（入库质检、临期登记）。
*   **诉求**: 拍一张照片，**秒级**给出日期；最好能顺带提示是否临期/过期。
*   **衡量**: 识别成功率与响应时间。

## 3. 竞品分析 (Competitive Landscape)

### 3.1 竞品划分

| 类别 | 代表 | 与我们的关系 |
| :--- | :--- | :--- |
| **一体化数据+训练平台** | Roboflow、Ultralytics Platform | 直接竞品（若走采购路线） |
| **标注工具** | Label Studio、CVAT | 局部替代方案（只解决标注一环） |
| **数据治理工具库** | FiftyOne、Cleanlab | 提供可借鉴的能力（重复检测、错标、防泄漏），非产品竞品 |
| **数据版本化工具** | DVC、lakeFS | 提供可借鉴的思路（快照、血缘），非产品竞品 |

| **通用 MLOps** | ClearML、W&B | 面向算法实验管理，不解决数据采集与标注 |

### 3.3 可借鉴的具体能力（来自竞品调研）

*   **Roboflow Health Check** 的检查项设计：`missingAnnotations` / `nullAnnotations` / `classDistribution` / 尺寸分布热力图 → 直接指导 [P0023 导入预检与清洗](./PRD/02_数据导入/P0023_导入预检与清洗.md)。
*   **Roboflow 版本快照机制**：Version 冻结 + `train/valid/test` 重平衡（70/20/10）+ `grouping=batch` 按批次分组切分 → 直接对应 P0041 与 P0100 的防泄漏切分。
*   **FiftyOne Brain** 的 `exact_duplicates` / `near_duplicates` / `mistakenness` / `hardness` → 对应 P0023 与 P0100 的算子。
*   **Cleanlab Datalab** 的标签错误与离群检测 → 对应标注质检（P0063）。
*   **ClearML** 的"代码定义 DAG + 步骤缓存 + 从失败点 clone 重跑" → 对应 P0101 的执行与重跑。
*   **Ultralytics Platform / Roboflow 的共同结论**：产品形态是**固定阶段 + 参数化**，没有一家做自由画布编排 → 指导 [P0100](./PRD/06_流水线/P0100_流水线阶段与算子.md) 明确不做画布。

### 3.4 我们的机会点 (Market Gap)

现成产品在"数据不出本机 + 采集作业链 + 无授权负担"这个交集上是空的。
对我们而言这不是市场机会，而是**自建的必要性证明**。

## 4. 产品需求与策略建议 (Product Strategy)

### 4.1 产品定位

**一句话**: 把杂乱的照片变成可复现、可上线、可迭代的检测模型的一体化内部工作台。

**边界**: 单机 Local-First、2~3 人规模、不做多租户、不做自由编排画布。
**可替换点**: 训练后端（`Trainer Backend` 接口）、标注题型、存储后端、调度执行器四处留缝。

### 4.2 必须做好的 Top 5 功能

1.  **数据集版本与血缘** —— 没有它，一切"可复现"都是空话。
2.  **导入预检与防泄漏切分** —— 直接决定 mAP 是真是假。
3.  **可用的标注器 + AI 预标注** —— 决定数据积累的速度。
4.  **基于 k3s 的训练任务调度与指标看板** —— 决定迭代的节奏。
5.  **模型仓库与评估报告** —— 决定"哪一版该上线"能不能有依据。

### 4.3 路线图 (Roadmap)

#### Phase 1: 骨架与共识
*   完成全部模块 PRD，锁定实体契约与接口边界。
*   产出：本仓库文档。

#### Phase 2: 最小闭环（先跑通一版）
*   数据导入 → 标注 → 训练 → 导出 ONNX 的端到端链路可跑；用极少量真实数据验证。
*   节点：单机 k3s，本机 GPU。
*   产出：一个能被小程序调用的检测模型。

#### Phase 3: 数据治理加固
*   预检清洗、防泄漏切分、重复检测、AI 预标注上线。
*   产出：mAP 可信、标注效率显著提升。

#### Phase 4: 部署与两端
*   模型服务发布、灰度回滚、端侧导出；微信小程序接入，RN 客户端接入。
*   产出：业务侧可实际使用的识别能力。

#### Phase 5: 多任务泛化（视需要）
*   同一条流水线迁移到其他视觉检测任务；OCR 第二阶段接入。
