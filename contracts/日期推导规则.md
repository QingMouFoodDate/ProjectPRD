# 《轻眸识刻》包装标示日期规则

> **候选版本**：`date-rules.v1`，依赖 [DATA.md](DATA.md) 中的 `evidence.v1` 与 `decision.v1`；真实日期引擎及实现测试尚待完成。
> **适用范围**：包装标示日期比较与状态推导，不推断食品安全或实际存储状态。

## 一、判定对象与可靠输入

系统仅对包装标示日期进行日历计算与状态比较。原始 Observation 不因日期推导而改变：

- 输入必须是完整不可变 Evidence，校验 schema_version、真实来源、会话归属与 evidence_hash；
- 仅满足真实来源、合法语义与对应版本置信策略的事实，方可置 `eligible_for_decision: true`；
- MANUAL 事实来自合法存档 Correction，confidence 固定为 null；采纳与冲突处置记录版本化策略，不覆盖原机器候选；
- MFG 表示生产日期；EXP 和 BEST_BEFORE 保留原始包装语义（BEST_BEFORE 投影至 exp_date 作标示期限比较，非安全保证）；
- 缺乏上下文的单一无类型日期串不能默认推定为 MFG 或 EXP。

## 二、观察时间与日历有效性约束

| 校验维度 | 标准定义与取值规范 | 边界要求与非法拒绝情形 |
| :--- | :--- | :--- |
| **基准时区** | 默认 `Asia/Shanghai`，必须写入有效 IANA 时区标识 | 严禁省略时区信息，时区数据库变更须记录版本 |
| **观察时间** | 服务端生成的 observed_at，带已知偏移的 RFC 3339 | 拒绝无偏移、未知偏移 -00:00 和尾随空白，不使用客户端或 EXIF 时钟 |
| **基准日期** | 将瞬时时间换算至目标时区后提取 `observed_date` | 不得直接截取字符串前十位，夏令时切换不改变自然日天数 |
| **日期合法性** | 真实公历四位年完整日期，0001-01-01 至 9999-12-31 | 拒绝二位年、不完整和不存在的月日；运算溢出拒绝，不截断年份 |
| **生成时间** | `generated_at` 记录决策生成的机器时间 | 仅作为操作生成审计记录，严禁参与 `remaining_days` 核心计算 |

## 三、保质期与日历加法

保质期统一结构为 `{value: 正整数, unit: DAY / MONTH / YEAR}`：

| unit | 算法规范 | 示例 |
| :--- | :--- | :--- |
| DAY | `derived_exp_date = mfg_date + value` 自然日（**不减 1**） | 2024-05-18 + 1 DAY -> 2024-05-19 |
| MONTH | 原日期加 value 个日历月；超出目标月末则截断至月末 | 2024-01-31 + 1 MONTH -> 2024-02-29 |
| YEAR | 加 `12 * value` 个日历月，同样执行目标月末截断 | 2024-02-29 + 1 YEAR -> 2025-02-28 |

- 候选规则采用“不计生产日为第 1 天”口径：`2024-05-18 + 12 MONTH -> 2025-05-18`（非 2025-05-17）；
- 月加法仅对最终目标月截断，不累加单月日号损失：`2024-01-31 + 2 MONTH -> 2024-03-31`；
- 闰年公历规则：可被 4 整除且不可被 100 整除，或可被 400 整除（2024 为闰年，2100 非闰年）。

## 四、必要证据选择与一致性

### 1. 可靠性前置条件

- 必要事实存在未解决冲突、非法日期、未来生产或非正区间 -> `UNDETERMINED`；
- 必要字段仅有不可靠候选 -> `UNDETERMINED / LOW_CONFIDENCE`；
- 必要证据缺失 -> `UNDETERMINED / INFORMATION_MISSING`。

语法非法日期不能进入合法 Evidence.fact；保留原文与 INVALID_DATE 警告，唯一必要候选非法时按缺少合法输入处理。DTO 自身不合法则拒绝输入。可靠 MFG 晚于 observed_date 或 EXP <= MFG 为时间冲突，不能先按超期判定。

### 2. 直接与派生到期日

1. 有可靠直接 EXP 时采用；已超期或剩余 0..30 天无需补 MFG，剩余 >30 天还需可靠 MFG 计算比例；
2. 同时具备可靠 MFG + shelf_life 时，须计算派生 EXP 并与直接 EXP 比较；两者不一致触发 `UNDETERMINED / EVIDENCE_CONFLICT`；
3. 无直接 EXP 但有可靠 MFG + shelf_life 时，采用派生 EXP，`snapshot.exp_date_is_derived = true`；
4. 直接与派生一致时采用直接 EXP，`exp_date_is_derived = false`；used_fact_ids 保留参与检查的真实 MFG、shelf_life 和 EXP；
5. 可靠 MFG + EXP 可以计算寿命，不强制 shelf_life；派生 EXP 引用真实 MFG 与 shelf_life，不生成虚假的来源事实。

### 3. 必要性与复核范围

复核仅针对本次必要输入。可靠 EXP 足以判定超期或 30 天内临期时，不因无关 MFG/shelf_life 候选缺失或不可靠而降级；但已有可靠 MFG 的时间检查和 MFG + shelf_life 的直接/派生一致性检查必须执行。非必要 storage_condition 问题只产生 warnings。

Decision.review_status 优先级顺序：

| 优先级 | review_status | 适用情形 |
| :--- | :--- | :--- |
| 1 | EVIDENCE_CONFLICT | 必要事实冲突、未来生产、EXP <= MFG 等逻辑错误 |
| 2 | LOW_CONFIDENCE | 无冲突但必要字段仅有不可靠候选 |
| 3 | INFORMATION_MISSING | 缺少本次判定必需的输入或寿命比例 |
| 4 | EVIDENCE_COMPLETE | 本次判定所需事实完整可靠且一致 |

## 五、标示期限判定顺序

定义自然日差：
- `remaining_days = exp_date - observed_date`（带符号整数日差）；
- 具备可靠 MFG + EXP 时，`total_lifetime_days = exp_date - mfg_date`（须为正整数）。

严格按以下顺序判定：

| 顺序 | 条件 | marked_status |
| :--- | :--- | :--- |
| 1 | 存在冲突、非法日期、低置信或缺少必需输入 | UNDETERMINED |
| 2 | 可靠 EXP 且 remaining_days < 0 | PAST_MARKED_PERIOD |
| 3 | remaining_days >= 0 且 remaining_days <= 30 | NEAR_EXPIRY |
| 4 | remaining_days > 30 且无可靠 MFG（无法计算比例） | UNDETERMINED |
| 5 | 有正 total_lifetime_days 且 remaining_days * 10 <= total_lifetime_days | NEAR_EXPIRY |
| 6 | 其余可靠、完整且一致的输入 | WITHIN_MARKED_PERIOD |

- 到期当天（remaining_days = 0）属于 NEAR_EXPIRY；次日（remaining_days = -1）属于 PAST_MARKED_PERIOD；
- 比例比较采用整数乘法，禁止除零与浮点近似。
- EXP-only 剩余 >30 天时，输出 UNDETERMINED / INFORMATION_MISSING，missing_fields 包含 mfg_date；只有不可靠 MFG 候选时优先 LOW_CONFIDENCE。月份/年份保留原始单位，不换算成固定天数。

## 六、候选日期解析矩阵

| 格式候选 | 合法示意 | 标准化输出 | 校验要点 |
| :--- | :--- | :--- | :--- |
| YYYY-MM-DD | 2024-05-18 | 2024-05-18 | 四位年双位月日、日历有效性 |
| YYYY/MM/DD | 2024/05/18 | 2024-05-18 | 分隔符一致 |
| YYYY.MM.DD | 2024.05.18 | 2024-05-18 | 排除小数与批号混淆 |
| YYYYMMDD | 20240518 | 2024-05-18 | 恰好八位且具备明确语义上下文 |
| YYYY年M月D日 | 2024年5月18日 | 2024-05-18 | 月日支持一或两位 |

格式矩阵是待实现候选，不表示已支持。正负测试覆盖二位年、不完整日期、非法闰日、混合分隔符、多余数字、同串多日期和批号歧义。未解析成功保留原文，不补世纪、月末或类型，也不以日历合法性证明 OCR 正确。

## 七、存储与开封提示

“冷藏保存”、“开封后尽快食用”等仅作为存储条件事实或 warnings/guidance 提示展示，不自动重算到期日，不作食品安全结论。

## 八、版本与历史重放

- 规则、解析/置信策略及相关时区数据库变更记录新版本，原版本与配置须保持可取得，不能同名改结果；
- 重放须取得原完整 Evidence、实际 JCS 哈希、原 observed_at、timezone、旧规则及 parser_version 对应配置和修正记录；先核验哈希与引用，再核对选中事实、派生值与二维状态，不使用当前时钟或仅用 snapshot；
- 哈希不一致、旧版本或原证据不可取得时拒绝可信重放。新观察时刻重查生成新 decision_id、observed_at 与 generated_at；重放或新规则评估均不覆盖原 Decision。

## 十、候选未决边界

- date-rules.v1 采用“不计生产日为第 1 天”的候选口径；包装明确其他计数或条件期限时需人工复核并另定版本；
- 冲突消歧策略与可靠性阈值须经实际评测校准；
- 原始 OCR 文字与检测框修正属于后续 C0，correction.v1 尚未定义这些字段；
- 语义、置信策略和时区数据库版本须通过不可变配置追溯；若现有字段无法无歧义关联，冻结前补契约。
