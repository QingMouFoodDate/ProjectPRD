# 《轻眸识刻》包装标示日期规则

> **版本状态**：`date-rules.v2`，依赖 [DATA.md](DATA.md) 的 `evidence.v1` 与 `decision.v2`；独立规则原型已通过 V01~V30 单元测试，待 M0 在线服务集成验收。
> **适用范围**：包装标示日期比较与期限提醒，不推断食品安全、实际保存情况或标签合规结论。

## 一、判定对象与可靠输入

输入为完整不可变 Evidence，先核验版本、实际哈希、来源、会话归属和解析配置。只有语义明确、合法且按关联策略可靠的事实可以用于判断。

- 原始 Observation 不因规则过滤、候选选择、人工修正或日期推导而改变。合法日期格式不等于原图日期识别正确。
- MANUAL 事实引用合法存档 Correction，confidence 为 null；修正的采纳及冲突处置须记录，不默认最后写入值胜出。
- MFG、EXP、BEST_BEFORE 的包装语义保留于原文和解析记录。BEST_BEFORE 只作对应标示日期比较，不改称食品安全保证；批号、无类型日期和消费保存期不混入 EXP。
- 有可靠直接 EXP 时可以独立比较期限，缺少 MFG 或 shelf_life 不自动要求补齐。只有按 MFG + shelf_life 推导时，才必须明确起算依据。

## 二、观察时间与日历有效性约束

| 校验维度 | 取值与处理 | 边界 |
| :--- | :--- | :--- |
| 时区 | 写入实际 IANA 标识，候选默认 Asia/Shanghai | 时区数据库版本由计算配置追溯 |
| observed_at | 服务端业务观察瞬时，带已知偏移的 RFC 3339 | 允许 Z；拒绝无偏移、-00:00、尾随空白，不使用客户端或 EXIF 时钟 |
| observed_date | 将瞬时转换到 timezone 后取本地日期 | 不截取时间字符串；日期差按自然日，不用固定24小时秒数 |
| 日期 | 完整真实公历 YYYY-MM-DD，0001-01-01 至 9999-12-31 | 拒绝二位年、部分日期、非法月日及运算溢出，不猜世纪或月末 |
| generated_at | 本次决策生成时间 | 不参与剩余天数计算或改变原 observed_at |

## 三、保质期与日历加法

保质期保留 `{value: 正整数, unit: DAY / MONTH / YEAR}`。月份和年份不换成固定天数。

国家卫健委对 GB 7718—2025 的[官方问答第三十六条](https://www.nhc.gov.cn/sps/c100087/202509/bc824a504ec34c27883da73f14c20d44.shtml)允许到期日从生产日期当日或次日起算。该标准于2027-03-16实施；适用版本及包装说明须核对，不能把本项目的算法当成唯一法定口径。

| 起算模式 | 本候选算法 | DAY 示例 |
| :--- | :--- | :--- |
| COUNT_FROM_NEXT_DAY | 先按单位一次加 value 的期限量，生产日不计第1天 | MFG 2024-05-18 + 1 DAY -> EXP 2024-05-19 |
| COUNT_FROM_MFG_DAY | 生产日计第1天；DAY 加 value - 1 个自然日 | MFG 2024-05-18 + 1 DAY -> EXP 2024-05-18 |
| 未知（双口径包络检验） | 当日起算与次日起算分别构建悲观下界与乐观上界 | 见下方双口径包络检验机制 |

MONTH/YEAR 的候选月加法只对最终目标月截断：2024-01-31 + 2 MONTH -> 2024-03-31；YEAR 按 12 * value 个日历月处理，2024-02-29 + 1 YEAR -> 2025-02-28。COUNT_FROM_NEXT_DAY 使用该结果；COUNT_FROM_MFG_DAY 的包含式日历月采用 `clamp_month_end(y, m + k, d) - 1 day`（例如 2024-01-01 + 1 MONTH 当日起算 -> 2024-01-31）。公历闰年按 4、100 和 400 年规则处理。

### 1. 双口径包络检验机制（Dual-Basis Envelope Verification）

当包装未明示起算口径（`start_mode == UNKNOWN`）时，推导引擎执行双口径包络定理以兼顾食品安全与消除无谓拒识：

1. **构建包络边界**：
   - 悲观下界（当日起算）：`EXP_lower = calc(MFG, shelf_life, COUNT_FROM_MFG_DAY)`
   - 乐观上界（次日起算）：`EXP_upper = calc(MFG, shelf_life, COUNT_FROM_NEXT_DAY)`，恒有 `EXP_upper = EXP_lower + 1 day`

2. **定理 1（双源交叉核验包络，对应第五.2 节与 V15）**：
   当包装同时存在直接 EXP、MFG 与保质期且起算未知时，构造包络区间 `[EXP_lower, EXP_upper]`：
   - 若 `direct_exp in [EXP_lower, EXP_upper]`，判定双源一致并直接采信直接到期日（`EVIDENCE_COMPLETE`），反推锁定隐含起算口径；
   - 若 `direct_exp not in [EXP_lower, EXP_upper]`，判定为未解决冲突，输出 `UNDETERMINED / EVIDENCE_CONFLICT`（`DERIVED_VS_DIRECT_MISMATCH`）。

3. **定理 2（单源保守下界推导与临界阻断，对应 V11 与 V29）**：
   当仅有 `MFG + shelf_life` 且起算未知时，1 天起算口径偏差在整个日历轴上**仅在两个单日跳变点**引发三态业务分类（在期 / 临期 / 超期）发生跳变：
   - **临界点 A（在期/临期跳变点）**：当且仅当 `observed_date == EXP_lower - T` 时，当日起算判定为 `NEAR_EXPIRY`，次日起算判定为 `WITHIN_MARKED_PERIOD`；
   - **临界点 B（临期/超期跳变点）**：当且仅当 `observed_date == EXP_upper` 时，当日起算判定为 `PAST_MARKED_PERIOD`，次日起算判定为 `NEAR_EXPIRY`。
   除上述两个单日临界点外，对任意其他观测日，双口径的三态判定结论恒等！
   
   **单源闭环推导规则**：
   - **临界与超短周期阻断**：若 `observed_date in {EXP_lower - T, EXP_upper}`，或者 `rem_lower <= 1 day`（临近到期的最后 48 小时高精度敏感窗口，含超短保鲜品 V11），系统拒绝保守近似，强制输出 `UNDETERMINED / INFORMATION_MISSING`，记录 `START_BASIS_UNKNOWN`，触发 Tier-2 人工确认起算口径；
   - **绝对超期**：若 `observed_date > EXP_upper`，无论按何口径起算均已超期，输出 `PAST_MARKED_PERIOD / EVIDENCE_COMPLETE`，采用 `EXP_lower` 并在 warnings 中标注包络超期；
   - **绝对安全在期**：若 `observed_date < EXP_lower - T`，无论按何口径起算均在期，输出 `WITHIN_MARKED_PERIOD / EVIDENCE_COMPLETE`，采用食品安全最保守下界 `EXP_lower` 作为选定 `exp_date`，并在 warnings 中标注 `CONSERVATIVE_LOWER_BOUND_APPLIED`；
   - **确定临期**：若 `EXP_lower - T < observed_date < EXP_upper` 且 `rem_lower > 1 day`，无论按何口径起算均属临期，输出 `NEAR_EXPIRY / EVIDENCE_COMPLETE`，采用保守下界 `EXP_lower` 作为 `exp_date`，并在 warnings 中标注 `CONSERVATIVE_LOWER_BOUND_APPLIED`。

### 2. 多条件与季节性动态保质期（Multi-Condition Shelf Life）

食品包装若标示不同存储条件（如“常温 30 天，冷藏 90 天”）或不同季节区间（如“4-10 月 6 个月，11-3 月 9 个月”），按以下规则处理：
- Evidence 层将多组标示提取为独立 `shelf_life` 事实分支，附带对应 `storage_condition` 标签；
- 若会话未提供经确认的履约存储条件或生产月份映射，推导引擎遵循食品安全保守原则，选取**最短有效期分支**作为基准计算，并在 `Decision.warnings` 载明所采用的条件假设与对应指引。

### 3. 计算依据与临期配置

`decision.v2.calculation_profile_id` 引用服务端保存的不可变计算记录，不由客户端传入。该记录至少包含：

| 内容 | 要求 |
| :--- | :--- |
| 身份与规则 | 唯一 calculation_profile_id、规则版本、创建时间；内容变化产生新 ID |
| 临期策略 | mode=FIXED_DAYS，near_expiry_days 为非负整数；M0 默认候选30天，其他阈值须明确配置 |
| 证据绑定 | evidence_id/hash、parser_version 和时区数据库版本；与 Decision 实际输入一致 |
| 起算绑定 | 需要推导时记录真实 MFG/shelf_life fact_id、起算模式、包装原文或经审核规范依据、适用范围和选择记录 |

起算依据不是新的视觉 fact。配置记录引用真实来源，不用“常用口径”补未知输入；直接 EXP 路线可没有起算绑定。一个会话存在多组日期或期限时，绑定仅适用于对应事实对，不能全局套用。配置、证据和来源在历史重放期内均可取得；无法可靠关联时拒绝可信重放。

固定天数临期是项目提醒策略，不是法律判定。寿命10%比例策略从 M0 移出，后续如引入须另行定义缺少 MFG 时的提示、规则版本与测试，不能重新阻断可靠直接 EXP 的基本期限比较。

## 四、必要证据选择与一致性

### 1. 可靠性前置条件

- 必要日期存在未解决冲突、未来可靠生产日期或 EXP < MFG -> UNDETERMINED / EVIDENCE_CONFLICT。
- 必要字段只有不可靠候选 -> UNDETERMINED / LOW_CONFIDENCE；没有合法必要事实或推导依据 -> UNDETERMINED / INFORMATION_MISSING。
- 非法原文日期不进入合法 Evidence.fact，保留原 Observation 和警告；DTO 自身非法则拒绝契约输入。
- MFG = EXP 不再一概当作非法区间；一天包含式期限可以同日结束。若已知同一期限口径或语义与同日矛盾，仍记录冲突。

### 2. 直接与派生到期日

1. 有可靠直接 EXP 时以它比较；有可靠 MFG 时仍检查未来日期及 EXP < MFG。
2. 只有 MFG + shelf_life 时，按相应事实对的有据起算绑定推导。若起算依据未知，按第三.1 节双口径包络定理区分非临界安全区保守下界推导与临界跳变窗口阻断；若单位不支持，exp_date 与派生标志为 null，输出 UNDETERMINED / INFORMATION_MISSING。
3. 直接 EXP 与派生值比较，仅在同一期限、单位、语义、起算依据均已确认时执行。不能选取恰好匹配直接值的口径来消除冲突。
4. 不一致时先查是否为不同期限、类型或合法起算差异。依据未知可保留直接 EXP 的判断并给出警告；已确认同一期限、同一口径仍不一致时，输出证据冲突。
5. 一致时采用直接值，派生标志为 false；used_fact_ids 保留直接值及一致性检查所用事实。仅派生时为 true，引用真实 MFG 和 shelf_life，不创建派生 MODEL fact。

### 3. 必要性与复核范围

只评价影响本次期限比较的必要事实。直接 EXP 足够时，非必要 MFG/shelf_life 缺失或低置信不降低日期结果；已有可靠 MFG 的时间检查不能跳过。无类型的多日期选择冲突、来源不一致或必须执行的同一期限核对矛盾，仍须复核。

| 优先级 | review_status | 情形 |
| :--- | :--- | :--- |
| 1 | EVIDENCE_CONFLICT | 必要事实未解决冲突、未来生产或确认的时间／期限矛盾 |
| 2 | LOW_CONFIDENCE | 无上述冲突，但必要候选不可靠 |
| 3 | INFORMATION_MISSING | 缺少必要日期、类型或推导依据 |
| 4 | EVIDENCE_COMPLETE | 本次必要输入可靠、足够且一致 |

非必要保存条件冲突、未知起算说明或缺失补充字段可以进入 warnings，不机械复制为日期复核状态。警告影响是否重大须按结果依赖判断，不能借此忽略真实必要冲突。

## 五、标示期限判定顺序

先取得可靠且一致的直接或派生 EXP，计算 `remaining_days = exp_date - observed_date`。使用不可变计算记录中的阈值 T，默认候选 T=30。

| 顺序 | 条件 | marked_status |
| :--- | :--- | :--- |
| 1 | 必要证据缺失、不可靠、冲突，或推导依据不成立 | UNDETERMINED |
| 2 | remaining_days < 0 | PAST_MARKED_PERIOD |
| 3 | 0 <= remaining_days <= T | NEAR_EXPIRY |
| 4 | remaining_days > T | WITHIN_MARKED_PERIOD |

到期当天为 NEAR_EXPIRY，次日为 PAST_MARKED_PERIOD。可靠 EXP-only 剩余31天，在默认配置下为 WITHIN_MARKED_PERIOD / EVIDENCE_COMPLETE，无需补 MFG。这些状态只比较包装标示日期，不保证实际食品安全。

## 六、候选日期解析矩阵

| 格式候选 | 合法示意 | 标准化输出 | 核验要点 |
| :--- | :--- | :--- | :--- |
| YYYY-MM-DD | 2024-05-18 | 2024-05-18 | 四位年双位月日、真实日历 |
| YYYY/MM/DD | 2024/05/18 | 2024-05-18 | 分隔符一致 |
| YYYY.MM.DD | 2024.05.18 | 2024-05-18 | 排除小数与批号 |
| YYYYMMDD | 20240518 | 2024-05-18 | 恰好八位并有日期类型依据 |
| YYYY年M月D日 | 2024年5月18日 | 2024-05-18 | 月日一或两位，核对实际 OCR |

格式尚待真实实现验证，不以矩阵存在宣称已支持。测试二位年、缺日、非法闰日、混合分隔符、多余数字、多日期、批号、生产／到期／最佳食用／消费保存期语义。保留候选与原文，不由规则或语言模型补造不可见日期；完整字段和类型正确性分别评测。

## 七、存储与开封提示

冷藏、阴凉保存或开封后期限进入事实与提示。没有真实开封时间、保存履约和独立规则依据时，不改写包装到期日，不产生新的食品安全期限。消费保存期及进口包装语义应独立核验，未定义的字段不混用 exp_date 接入。

## 八、版本与历史重放

- 当前新候选使用 decision.v2、date-rules.v2 和 calculation_profile_id；Observation、Evidence、Correction 仍为 v1。改变版本和配置必须显式登记。
- [原v1日期规则](archive/日期推导规则.v1.md)及 [Decision v1 Schema](schemas/decision.v1.schema.json)保留，旧36项预期不在原版本名下改变。旧 payload 不自动套入新规则。
- 重放固定完整 Evidence/hash、原 observed_at/timezone、旧规则、计算配置、解析策略和来源记录；先验证完整性与引用，再检查选定事实、派生投影和状态。
- 版本、配置或证据缺失，拒绝可信重放，不退回当前默认配置。新观察日、新规则或新配置评估产生新 Decision，不覆盖原记录；GET 返回已存结果，不随当天时钟重算。

## 十、候选未决边界

- MONTH/YEAR 的包含式计算、适用标准与标签特殊语义仍需原规范与实际包装验证；不足时复核，不默认补口径。
- 起算依据、解析／置信策略及临期阈值通过不可变 calculation_profile_id 追溯；它不是食品监管合规证明。
- calibration、候选选择和处理策略属于研究；在线自动重试、补拍动作及图像变体的协议尚待定义，不能提前宣称已接入。
- 起算模式（start_mode）修正支持独立重算闭环：当用户通过 Correction 提交 start_mode 修正时，系统不写入 Evidence.facts，而是派生并保存新的 CalculationProfile 记录，更新 calculation_profile_id 并绑定所选起算口径，基于原 Evidence 重新触发生成新版本 Decision；四类语义字段纠偏则继续通过写入 Evidence.facts 产生新事实版本。
- 真日期引擎、API、模型输入输出和跨版本重放通过后才能评审冻结；本次静态校验不等于运行验收。
