1. 全局说明
   名词解释：每个行业都有专业术语，可以提前将晦涩难懂的术语提前做好解释，便于达成共识，更好沟通；
   统一异常处理：一些异常的统一处理；
   所有涉及全局的描述，都可以罗列在这里。

2. 项目背景
   背景 (Context): 业务背景是什么？为什么我们现在要启动这个项目？
   问题陈述 (Problem Statement): 我们正在解决哪些具体的痛点？
   目标与成功指标 (Goals & Success Metrics):
   北极星指标 (North Star Metric): 衡量成功的核心首要指标。
   次要指标: 重要的不可忽视的指标。
   风险与规避 (Risks & Mitigation): 技术、产品或运营层面的风险及应对方案。

3. 价值模型
   方案：针对这个问题，所提供的解决方案概述；
   目标：期望获得多少价值指标提升；

4. 项目范围
   项目范围对应搭框架部分，将功能结构图在此处罗列；
   In Scope / Out of Scope 必须显式写出。

5. 业务流程
   业务流程对应定流程部分，将核心业务流程、子系统业务流程在此处罗列。
   状态机必须使用 Mermaid `stateDiagram-v2`，交互必须使用 `sequenceDiagram`。

6. 用户分析
   6.1 用户画像 (User Personas)：角色、核心职责、核心诉求、核心痛点。
   6.2 用户链路图 (User Journey Map)：使用 Mermaid 时序图或流程图展示高层级的业务流。

7. 功能需求
   功能是从系统的角度来看，我们还要考虑用户角度，所以我们采用用户+功能的方式来描述需求。
   每个功能以 `### M0x.F0y <中文名> (<English>)` 为标题，包含：
   - 用户故事: 作为…，我希望…，以便…
   - 逻辑与业务规则: 前置条件 / 主流程 / 后置条件
   - 验收标准: 必须使用 Gherkin (Given/When/Then) 代码块
   - 边界情况与异常处理: 使用表格罗列

8. 技术架构与数据模型
   本章节旨在连接产品设计与工程实现。不写 API 设计，只传递必要的逻辑和数据实体信息。
   8.1 数据实体：用表格描述数据对象实体（字段名 / 类型 / 必填 / 说明 / 约束）
   8.2 状态机 / 逻辑流：使用 Mermaid 状态图展示

9. UI/UX 规格说明
   使用 ```text 围栏绘制 ASCII 线框图；交互元素与表单使用表格描述。

10. 非功能性需求 (NFR)
   性能 (Performance): 例如 API 响应时间 < 200ms (P95)。
   安全 (Security): RBAC 要求、数据加密。
   兼容性 (Compatibility): 浏览器/设备支持范围。
   可扩展性 (Scalability): 并发目标。
