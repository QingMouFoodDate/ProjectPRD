# 《轻眸识刻》文档编写规范

> **定位**：团队新增或修订产品规格与技术文档时的统一撰写标准与结构模版

---

## 一、 文档撰写与排版原则

1. **客观严谨，专业克制**：
   - 描述功能场景、接口出入参及验收标准，杜绝公文式套话与营销化措辞（如避免使用“神经中枢”、“唯一绝对依据”、“最大化压榨”等过度表达）；
   - 正式技术文档中严禁使用装饰性表情符号（emoji）；
   - 数学公式与符号使用纯文本表达（例如映射用 `->`，乘除用 `*`、`/`，范围用 `>=`）。
2. **标题无括号规范**：
   - 所有 Markdown 各级标题（`#`、`##`、`###`、`####`）末尾严禁出现任何中英文括号及其附注内容。
3. **架构图目录粒度规范**：
   - 架构树状图除根目录下核心入口文件外，所有子目录仅展示文件夹及子文件夹层级，严禁罗列子目录内部具体文件。
4. **隐私与环境解耦**：
   - 严禁在文档中出现任何本地专属私有路径（如本地 `reports`、`data` 等离线文件夹字样）。
5. **判定对象伦理底线**：
   - 涉及保质期状态，判定对象严格限定为“包装标示状态”，严禁直接输出“绝对安全可食用”等主观断言。

## 二、 PRD 编号与命名规则

| 规则维度 | 格式规范 | 实际示例 |
| :--- | :--- | :--- |
| **模块目录** | `序号_模块中文名` | `01_数据采集/`、`04_标注中心/` |
| **文档命名** | `编号_功能中文名.md` | `P0001_采集项目与SOP.md`、`P0065_字符转写与OCR标注.md` |

### 模块编号区间表
- `01_数据采集`：P0001 ~ P0005
- `02_数据导入`：P0020 ~ P0024
- `03_数据管理`：P0040 ~ P0046
- `04_标注中心`：P0060 ~ P0066
- `05_训练平台`：P0080 ~ P0087
- `06_流水线`：P0100 ~ P0101
- `07_部署推理`：P0110 ~ P0113
- `08_端接入`：P0120 ~ P0122
- `09_系统管理`：P0130 ~ P0132

## 三、 标准 PRD 文档结构模版

编写新需求或技术规格时参考以下 Markdown 结构：

```markdown
# P00XX 功能名称

## 1. 功能概述与价值
- **核心定位**：解决什么问题，输入是什么，输出是什么。
- **业务价值**：服务于哪条业务链路。

## 2. 交互与业务流程
- 核心流转步骤（建议附 Mermaid 流程图或时序图）。
- 异常场景与边界处理（弱网、反光、空输入等）。

## 3. 数据与接口契约
- 涉及的 API 类别与调用时机。
- 关键数据字典与枚举值定义。

## 4. 验收标准
- 验收点 1：能够正常接收参数并返回预期结果；
- 验收点 2：边界异常返回合规错误码。
```
