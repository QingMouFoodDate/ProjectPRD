# 轻眸识刻 产品需求文档编写规范

> **定位**：团队后续新增或修订产品需求规格（PRD）时的统一撰写标准与结构模版。  

---

## 一、 文档撰写原则

1. **客观准确，直奔主题**：
   - 描述功能场景、接口出入参及验收标准，避免抒情与公文式长篇套话；
2. **严谨规范，排版专业**：
   - 正式技术文档中严禁使用装饰性表情符号（emoji）；
   - 数学公式与维度计算使用纯文本表达（例如映射用 `->`，乘除用 `*`、`/`，范围用 `>=`）；
3. **任务解耦，留有余地**：
   - 强调输入输出规格（契约协议），不过度硬编码底层的具体开发框架与环境。

---

## 二、 PRD 编号与命名规则

| 规则维度 | 格式规范 | 实际示例 |
| :--- | :--- | :--- |
| **模块目录** | `序号_模块中文名` | `01_数据采集/`、`04_标注中心/` |
| **文档命名** | `编号_功能中文名.md` | `P0001_采集项目与SOP.md`、`P0065_字符转写与OCR标注.md` |

### 模块编号区间表
- `01_数据采集`：P0001 ~ P0005
- `02_数据导入`：P0020 ~ P0024
- `03_数据管理`：P0040 ~ P0046
- `04_标注中心`：P0060 ~ P0066
- `05_训练平台`：P0080 ~ P0087
- `06_流水线`：P0100 ~ P0101
- `07_部署推理`：P0110 ~ P0113
- `08_端接入`：P0120 ~ P0122
- `09_系统管理`：P0130 ~ P0132

---

## 三、 标准 PRD 文档结构模版

编写新文档时可直接参考以下标准 Markdown 结构：

```markdown
# P00XX 功能名称

## 1. 功能概述与价值
- **核心定位**：解决什么问题，输入是什么，输出是什么。
- **业务价值**：服务于哪条业务链路。

## 2. 交互与业务流程
- 核心流转步骤（建议附 Mermaid 流程图或时序图）。
- 异常场景与边界处理（弱网、反光、空输入等）。

## 3. 数据与接口契约
- 涉及的 HTTP API 路径及请求/响应 JSON Schema。
- 关键数据字典与枚举值定义。

## 4. 验收标准
- [ ] 验收点 1：能够正常接收参数并返回预期结果；
- [ ] 验收点 2：边界异常返回合规错误码。
```
