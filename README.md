## 二、 组织 6 大仓库矩阵全景

整个轻眸识刻系统按技术栈与运行环境解耦为 6 个核心仓库：

| 仓库名称 (GitHub) | 中文定位 | 技术栈属性 | 核心职责 |
| :--- | :--- | :--- | :--- |
| **`ProjectDocs`**<br>*(即 ProjectPRD)* | **设计与文档中枢** | Markdown / Docs | **系统架构设计、接口契约、质量规范、四级能力规划与需求规格库**。不存放业务代码。 |
| **[`TrainPlatform`](https://github.com/QingMouFoodDate/TrainPlatform)** | **业务后端与平台** | Python / Go / DB | **多端统一 API 服务、识别会话编排、集中样本存储、日期语义与状态决策引擎**。 |
| **[`ModelTrain`](https://github.com/QingMouFoodDate/ModelTrain)** | **算法研发与评测** | PyTorch / Python | **小目标检测、微型字符 OCR、多分支感知、8 项消融实验与轻量模型导出**。 |
| **[`WebClient`](https://github.com/QingMouFoodDate/WebClient)** | **Web 核心原型系统** | 前端现代框架 | **大创官方核心预期成果：多图会话、原生相机/条码解析、双重视图、状态卡片展示**。 |
| **[`MobileClient`](https://github.com/QingMouFoodDate/MobileClient)** | **移动端客户端** | Flutter / 原生等 | **面向移动场景的实拍工具、传感器防抖、本地离线台账、端侧轻量推理探索**。 |
| **[`WxClient`](https://github.com/QingMouFoodDate/WxClient)** | **微信小程序端** | 微信原生 / Taro 等 | **面向消费者的轻量免安装备选通道、长辈关怀大字模式、微信一键社交分享卡片**。 |

## 四、 工程协作原则

1. **架构契约先行，实现细节灵活选型**：
   - 团队协作以 `contracts/` 目录下的接口协议与模型交付规约为共同准则；
   - 只要契约输入输出对齐，各端研发可结合实际技术生态自主选用合适的实现框架。
2. **渐进迭代，优先保障核心闭环**：
   - 项目优先保障 C0 级申报承诺能力闭环，以 TrainPlatform 配合 WebClient 与 ModelTrain 跑通“传图 ➔ 识别 ➔ 标示推算”的最小可用流程。
3. **严守数据真实性底线**：
   - 全体组员在采图与审核时严格遵循 `standards/数据质量规范.md`；
   - 坚决杜绝任何算法伪造标签、手绘红圈标记与拼图大板粗审，严守数据纯洁性底线。
