# 轻眸识刻设计与文档中枢

> **项目名称**：轻眸识刻——基于小目标驱动的食品包装日期智能识别系统  
> **组织归属**：`QingMouFoodDate` GitHub 协作组织  
> **本仓定位**：**全域设计与规范中枢**（系统架构设计、需求池、跨仓技术契约与质量标准）

---

## 一、 权威依据

项目核心承诺以立项申报书为准，答辩材料用于说明技术主线，演进论证材料仅作为远期规划参考。C1~C3 能力属于演进候选，不构成当前交付承诺。

---

## 二、 稳定产品定位

系统围绕“真实图像采集、日期区域定位、受限字符识别、标示状态推导和人工纠偏”建立统一的产品与技术边界。具体阶段进度、里程碑状态和验收记录由推进文档单独维护，不作为本仓库稳定规范的组成部分。

---

## 三、 中枢文档导航

建议按以下顺序阅读：

1. `README.md`：了解项目定位、权威依据和文档边界；
2. `REQUIREMENTS.md`：了解产品范围、能力分级和非目标；
3. `ARCHITECTURE.md`：了解仓库职责、系统分层和核心数据流；
4. `contracts/`：了解跨仓 API、数据模型和模型交付约束；
5. `RESEARCH.md`：了解算法基线、科研假设和评估指标；
6. `standards/`：了解数据质量和工程协作要求；
7. `ROADMAP.md`：查看内部阶段推进参考和交付准入条件。

跨仓协作优先参考 `REQUIREMENTS.md`、`ARCHITECTURE.md` 和 `contracts/`；`ROADMAP.md` 仅用于内部推进，不代表项目当前完成状态。

| 文档定位 | 文档路径 | 核心内容概述 |
| :--- | :--- | :--- |
| **产品与架构** | [`REQUIREMENTS.md`](REQUIREMENTS.md)、[`ARCHITECTURE.md`](ARCHITECTURE.md) | 产品边界、系统分层、仓库职责和非目标 |
| **跨仓契约** | [`contracts/`](contracts/) | API、数据模型和模型交付约束 |
| **研发与推进** | [`RESEARCH.md`](RESEARCH.md)、[`ROADMAP.md`](ROADMAP.md) | 科研假设、评估指标和内部推进参考 |
| **质量与协作** | [`standards/`](standards/) | 数据质量、命名、提交和工程协作规范 |

## 五、 工程协作原则

1. 跨仓实现以本仓库的需求、架构和契约为准；
2. 命名、分支、提交、测试和质量要求遵循 `standards/`。
