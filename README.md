# 轻眸识刻设计与文档中枢

> 面向全域系统规范、需求池、跨仓技术契约与质量标准的单一事实来源
>
> **工程状态**：八仓职责架构已批准 · 在线离线彻底解耦 · M0 核心原型推进中

ProjectPRD 作为全域“设计与规范中枢”，统筹管理需求规格、系统架构、跨仓契约、算法实验与推进路线。全域代码仓库接口实现、数据校验与开发行为均以此仓为单一事实来源（SSOT）。

## 一、权威依据与目标分级

项目核心承诺以申报书为准绳，答辩材料阐明技术主线，论证材料作为技术储备：

| 阶段标识 | 核心定位与研发范围 | 交付验收要求 |
| :--- | :--- | :--- |
| **C0 核心目标** | 单图与多图会话流、小目标检测、微型字符 OCR、标示推导与人工纠偏闭环 | 系统最终验收基准 |
| **C1 增强扩展** | 复杂包装形变自适应、局部图像增强与条码弱辅助对齐 | C0 跑通后的工程增强 |
| **C2/C3 远期储备** | 移动端传感器防抖辅助、适老化大字关怀模式与端侧轻量化推理探索 | 远期架构与技术储备 |
| **M0 优先验证** | C0 单图主链路切片：选图 -> 上传 -> 检测与识别 -> 决策 -> 双重视图展示 | 当前优先拉通的验证闭环 |

## 二、产品稳定定位与法定边界

系统聚焦食品包装日期智能识别与语义推导，核心边界严格限定为**包装标示状态推导**：

1. **法定对象受限**：系统仅对包装客观印刷文本进行检测与日历规则计算，严禁向用户直接断言食品是否绝对可食用或卫生安全结论；
2. **稳定八仓矩阵**：全系统划分为 8 个职责明确的独立代码仓库，不随意增删、合并或更名仓库；
3. **在线离线严格解耦**：InferPlatform 负责在线 API 与实时推理，TrainPlatform 负责样本治理与训练调度，ModelTrain 负责算法网络攻关。

## 六、工程协作与质量原则

- **架构决议至上**：跨仓代码实现必须对齐 [系统架构.md](系统架构.md) 中的边界划分；
- **模型生命周期隔离**：TrainPlatform 负责治理留痕（`register / validate / release`），InferPlatform 负责在线加载与安全回滚（`activate / rollback`）；
- **数据流闭环纪律**：用户纠偏在在线层即时更新会话决策；晋升为离线样本必须经 TrainPlatform 审核，严防标签污染；
- **代码提交规范**：遵循 Conventional Commits 格式 `<emoji> <type>: <简明中文改动>`；
- **资产与代码隔离**：大容量图像与模型文件绝不入 Git 仓库，敏感配置通过受控环境变量注入。
