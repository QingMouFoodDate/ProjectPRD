# 《轻眸识刻》数据质量规范

> **规范性质**：已批准职责设计下的数据质量要求，字段和门禁实现仍待契约评审与开发
> **适用范围**：来源许可、采集、清洗、标注审核、切分冻结及训练回流
> **责任边界**：TrainPlatform 治理离线数据与审核；ModelTrain 只读冻结版本；InferPlatform 管理在线资产与业务纠偏

---

## 一、 核心质量底线

数据进入训练或评测前必须满足以下底线，不能以哈希、用户修正或自动规则替代原图审核：

1. **零算法伪造与程序脑补**：严禁算式生成、取模循环、随机填充或程序脑补标签；OCR 真值和包装文字转录必须来源于原图可见内容。日期规则产生的派生字段单独标记来源和规则版本，不能冒充原文或人工真值；
2. **强制单张原图无损审阅**：永久禁止将多张图片拼合成 4x4、2x2 等 Grid 形式粗审；严禁编写拼图脚本；审阅必须一次一张打开本地原图，全分辨率逐像素细查画面四个边缘角落与打码主体。

---

## 二、 标准基准集排除规则

为防止带偏小目标检测网络先验或破坏标准基准集的真实分布，凡出现以下任一特征不得进入标准正样本基准集。若保留用于 negative 或 hardcase 研究，须有合法来源并独立审核、标记和隔离，不能与标准正样本混记：

1. **人为手绘涂鸦与标记圈**：手工用红笔、记号笔、手机画图圈出的红圈、椭圆、指认箭头和批注线等；
2. **自媒体营销大字幕与横幅**：短视频截屏中横贯画面的醒目营销大字（如“注意看”、“临期食品能不能买”）、大标题、大表情包遮挡；
3. **电商广告图与印码设备展示**：纯白底渲染电商产品图、手动打码机/喷码机设备本身的商品广告宣传图；
4. **非食品预包装**：纯五金配件、工业用盐、医用耗材、日化香水、药品药盒、保鲜袋盒等非食品流通品；
5. **不可见字段**：未拍到、未看清或语义不确定字段标为 `null` 并记录原因，不能用推导值填入原文标签；不符合研究用途或许可要求时剔除；
6. **完全无打码或严重缺损**：整图仅有配料表文字而无实物打码；关键日期数字缺失被严重截断；打码区域被反光完全吞噬呈死白一片不可辨识。

---

## 三、 四项生活环境平衡容差标准

兼顾生活实况与组员采集积极性，在守住真实底线的前提下，实施实用平衡容差：

1. **微小角标与相机微水印容限**：画面边缘角落存在不侵入食品包装主体、不触碰遮挡打码区域的单侧极微小平台角标或手机拍照时间水印角标允许保留；全屏半透明防盗水印与正中央居中大水印坚决淘汰；
2. **光影与金属塑料曲面反光容限**：易拉罐金属曲面、塑料袋包装褶皱处的自然轻微反光或漫反射，只要核心日期数字关键笔画清晰可辨、整体字意无歧义即可通过；反光强白斑覆盖并融毁核心笔画坚决淘汰；
3. **单排独立工业打码标注容限**：唯一清晰打码数字可采纳并按可见内容转录；只有包装明确注明“生产日期见罐底/见封口”等语义且关联图可追溯，才标为 MFG。仅凭日期形状或“见罐底”不能推定生产日期，缺少语义证据时保留未知类型；
4. **真实生活拍摄场景与手持容限**：自然真实手持（手指露在包装边缘）、超市货架实拍、家庭桌面就餐环境等生活实况，只要包装主体居中突出、打码区域对焦清晰即可通过。

## 四、 三大合规采图模式与实体转录

### 1. 三大合规拍摄模式
- **模式 A · 全局说明与局部打码协同**：一张拍全景背标文字（包含品类名、保质期天数或保存条件），一张拍微距打码区域特写，通过多图会话关联；
- **模式 B · 微距打码主体单图**：镜头贴近打码区域，对焦清晰，打码数字占据画面核心视场；
- **模式 C · 条形码与打码辅助关联**：辅助拍摄包装侧面或底面的 EAN-13 商品条形码，与打码图同属一次采集会话。

### 2. 三类核心文本实体
- **生产日期（MFG）**：包含“生产日期”、“PROD DATE”、“MFG”及对应数字串；
- **到期日（EXP）**：包含“保质期至”、“有效日期”、“EXP DATE”、“BEST BEFORE”及对应数字串；
- **保质期说明（SHELF_LIFE）**：包含保质期时长（如“12个月”、“180天”）及常温冷藏要求。保留原始数值、单位和条件；月份/年份不能无依据固定换成天数。

上述采图模式是目标采集规范，不表示多图会话或条码能力已实现。M0 使用单图切片，关联采集和完整展示保留在后续范围。

## 五、来源与使用许可

每项资产须登记可追溯的采集方式、来源标识、采集时间、提供方或授权凭据、许可范围及限制。至少区分训练、评测、公开展示和再次分发，来源可下载不等于获准使用。

- 自行拍摄仍须处理画面内人脸、私人信息、拍摄限制和用户授权；第三方图片须有允许相应用途的许可或明确授权；
- 来源或许可不明者先隔离，不能进入冻结训练/评测集，也不能公开展示；限制撤销或发生变化时记录影响版本及处置；
- InferPlatform 的在线业务授权不自动授予 TrainPlatform 训练使用权。纠偏回流须有可追溯授权，再接受独立审核；
- 公开文档只说明规范，不公开原图、用户记录、授权凭据、私有地址或秘密。权限按用途和资源归属控制。

## 六、三类标注与审核

| 标注层 | 最小要求 | 禁止混用 |
| :--- | :--- | :--- |
| bbox 检测标注 | 原图尺寸、坐标约定、日期区域框、边界合法、目标完整；记录遮挡/截断/不可读；派生切片保留原图与变换关系 | 不以切片局部坐标冒充原图坐标，不把文本可读性等同于是否存在目标 |
| OCR 转录标注 | 框或切片关联、可见原文、空格/分隔符/多行规则、不可读标记；逐字符核对 | 不用日期推算、词典纠错或模型预测自动充当真值 |
| 语义标注 | MFG/EXP/SHELF_LIFE 与未知类型、语义依据、原始单位、保存条件、关联图与字段来源 | 不将日期形状直接当日期类型，不将派生日期当包装原文 |

标注须记录规范版本、标注记录、审核记录和争议处置；机器预标只能作为待审输入。必填元数据必须完整，内容缺失或不可读字段允许 `null` 并附原因，不伪造非空值。冻结前逐张审核原图及对应标注，分歧未解决者隔离；字段名称由候选数据/训练契约统一，不宣称当前清单已具备全部字段。

## 七、group_key 切分与防泄漏

切分由 TrainPlatform 治理，ModelTrain 不得自行重切分。`group_key` 表示不可跨 split 的关联组，先确定分组策略再切分：

1. 同一实物、采集会话、原始图与其裁剪/缩放/增强衍生图、精确重复及确认的近重复归同组；结合批次或来源关联进一步归组。
2. 若评测宣称跨商品、批次或来源泛化，须把相应商品/批次/来源也作为隔离维度，不能仅用不同图名证明独立。
3. 同组只进入 train、validation、test 中一个 split；记录映射、分组策略、切分版本与配置，冻结前检查组集合无交集。
4. 先分组切分，再生成训练增强或裁剪；派生图继承原组和 split，不增加独立样本计数。
5. 测试集不用于调阈值、字表、纠错权重、量化校准或选模型。新增近重复或关联关系时重新审核影响，产生新版本，不静默修改冻结测试集。

## 八、冻结审核与难例隔离

- **冻结版本**：绑定原图完整性摘要、标注规范与版本、来源许可记录、审核结论、group_key/split 映射及版本清单；冻结后只读，修改须产生新版本并重新审核影响。
- **训练资格**：在线纠偏仅在 InferPlatform 业务接受后立即重算，不等于训练合格。TrainPlatform 对授权、可见真值、标注质量与组关系独立审核，保留待审、通过、拒绝及理由；未审/拒绝不得进入训练冻结版本。
- **negative 隔离**：没有目标但合法真实的图像可作为负样本，明确“无目标”与“存在但不可读”的差异，独立标记并报告误检，不能混充正样本。
- **hardcase 隔离**：反光、遮挡、截断、粘连、冲突或干扰样本单独标记、分层和版本化；不得通过偷偷删除难例提高标准集指标。
- **用途隔离**：标准集、negative/hardcase 研究集与待审纠偏池分别管理；相互关联仍须共享防泄漏分组约束。若将合格负样本或难例纳入训练，须显式审核组成和版本，评测分层不混记。

## 九、自动化门禁与人工复检

每次入库、标注、切分或冻结变更都先核验、后执行、再复检。具体命令由实现仓声明，未提供真实入口前标为待实现，本文不提供占位命令或声称门禁已运行。

| 检查 | 要求与限制 |
| :--- | :--- |
| 清单与文件映射 | 稳定 ID 唯一，每条图像记录关联存在文件，声明范围内无遗漏/悬空；多框标注使用明确关联，不以目录总文件数代替映射校验 |
| SHA-256 | 验证文件完整性与精确重复，防止改名重复入库；不是拍摄真实性、许可或标注正确性的证明 |
| pHash | 提供近重复候选；算法与距离阈值须登记并验证，由人工复核同物/同源关系；不使用无依据的统一固定阈值作为通行证 |
| 标注与类型 | bbox 合法、OCR 与语义来源一致，必填元数据/枚举合法，缺失和不可读有显式记录 |
| 来源与冻结 | 许可覆盖用途、审核可追溯、group_key 无跨 split 泄漏、冻结摘要一致、negative/hardcase 与待审池隔离 |

任何哈希结果都不能替代单张原图审阅。门禁失败先定位原因，不能删改难例、补造字段或篡改清单以制造通过结果。
