# 《轻眸识刻》数据质量规范

> **规范性质**：已批准职责设计下的数据质量要求，字段和门禁实现仍待契约评审与开发
>
> **适用范围**：来源许可、采集、清洗、标注审核、切分冻结及训练回流
>
> **责任边界**：TrainPlatform 治理离线数据与审核；ModelTrain 只读冻结版本；InferPlatform 管理在线资产与业务纠偏

---

## 一、 核心质量底线

数据进入训练或评测前必须满足以下底线，不能以哈希或自动规则替代原图审核：

1. **零算法伪造与程序脑补**：严禁算式生成、取模循环、随机填充或程序伪造标签；OCR 真值和包装文字转录须来源于原图可见内容。派生字段单独标记来源与规则版本，不得冒充原文或人工真值；
2. **强制单张原图审阅**：禁止拼图粗审（如 4x4 Grid）或编写拼图脚本；审阅须逐张打开本地原图，在全分辨率下查验画面边缘与打码主体。

---

## 二、 标准基准集排除规则

以下特征不得进入标准正样本基准集。用于 negative 或 hardcase 研究时须有合法来源，并独立审核、标记和隔离：

| 序号  | 排除违规特征 | 典型表现形式                                             | 规范处置手段             |
| :---: | :----------- | :------------------------------------------------------- | :----------------------- |
| **1** | 人为标记涂鸦 | 红笔圈出、荧光笔标记、指引箭头或手机画图批注             | 坚决剔除出正样本集       |
| **2** | 营销字幕遮挡 | 短视频截屏中的巨大营销标题、横幅大字幕与表情包           | 坚决剔除出正样本集       |
| **3** | 电商宣传渲染 | 纯白底商业产品渲染图、工业喷码机设备本身的广告宣传图     | 坚决剔除出正样本集       |
| **4** | 非食品流通品 | 五金紧固件、医用耗材、日化香水、药品药盒、农药肥料       | 坚决剔除出正样本集       |
| **5** | 字段缺失未拍 | 画面未拍到日期、文字被手指完全遮挡或语义不确定           | 对应字段置 `null` 并隔离 |
| **6** | 打码严重损毁 | 只有配料表而无实物打码、关键数字磨损截断、强反光死白过曝 | 坚决剔除出正样本集       |

## 三、 四项生活环境平衡容差标准

生活拍摄中的轻微干扰按下表判断，以日期内容是否清晰可见为准：

| 容差考核维度       | 允许通过标准（合格）                                   | 坚决淘汰标准（不合格）                             |
| :----------------- | :----------------------------------------------------- | :------------------------------------------------- |
| **画面水印与角标** | 包装主体边缘微小时间水印、单侧微型平台角标             | 居中大面积半透明防盗水印、横贯包装正面的大水印     |
| **光影曲面反光**   | 易拉罐金属曲面、塑料袋褶皱处的轻微漫反射，笔画清晰     | 强白斑完全吞噬数字核心笔画、反光导致文字融毁不可读 |
| **单排打码语义**   | 单排数字清晰可辨，严格按可见字符转录，未见语义标未知   | 仅凭数字形状强行脑补推断为生产日期（MFG）          |
| **手持生活实况**   | 手指露在包装边缘的手持实拍、超市货架自然抓拍、家庭桌面 | 严重手抖模糊、对焦脱靶、包装主体脱离画面中心视场   |

## 四、 三大合规采图模式与实体转录

### 1. 三大合规拍摄模式

- **模式 A · 全局说明与局部打码协同**：一张拍全景背标文字（包含品类名、保质期天数或保存条件），一张拍微距打码特写，通过多图会话关联；
- **模式 B · 微距打码主体单图**：镜头贴近打码区域，对焦清晰，打码数字占据画面核心视场；
- **模式 C · 条形码与打码辅助关联**：辅助拍摄包装侧面或底面的 EAN-13 商品条形码，与打码图同属一次采集会话。

### 2. 三类核心文本实体

- **生产日期（MFG）**：包含“生产日期”、“PROD DATE”、“MFG”及对应数字串；
- **到期日（EXP）**：包含“保质期至”、“有效日期”、“EXP DATE”、“BEST BEFORE”及对应数字串；
- **保质期说明（SHELF_LIFE）**：包含保质期时长（如“12个月”、“180天”）及常温冷藏要求。保留原始数值、单位和条件；月份/年份不能无依据固定换算为天数。

M0 优先使用单图切片，关联采集和完整展示保留在后续阶段。

## 五、 来源与使用许可

每项资产须登记可追溯的采集方式、来源标识、采集时间、提供方或授权凭据、许可范围及限制。至少区分训练、评测、公开展示和再次分发：

- 自行拍摄须处理画面人脸、隐私与用户授权；第三方图片须具备明确授权许可；
- 来源或凭据不明者先隔离，不能进入冻结训练/评测集，也不能公开展示；
- InferPlatform 的在线业务授权不自动授予 TrainPlatform 训练使用权。纠偏回流须具备可追溯授权并接受独立审核；
- 公开文档只说明规范，严禁泄露原图私有地址、用户隐私或凭据。

## 六、 三类标注与审核

| 标注层        | 最小要求                                                                                       | 禁止混用                                                       |
| :------------ | :--------------------------------------------------------------------------------------------- | :------------------------------------------------------------- |
| bbox 检测标注 | 原图尺寸、坐标约定、日期区域框、边界合法、目标完整；记录遮挡/截断/不可读；派生切片保留原图映射 | 不以切片局部坐标冒充原图坐标，不把文本可读性等同于是否存在目标 |
| OCR 转录标注  | 框或切片关联、可见原文、空格/分隔符/多行规则、不可读标记；逐字符核对                           | 不用日期推算、词典纠错或模型预测自动充当真值                   |
| 语义标注      | MFG/EXP/SHELF_LIFE 与未知类型、语义依据、原始单位、保存条件、关联图与字段来源                  | 不将日期形状直接当日期类型，不将派生日期当包装原文             |

标注须记录规范版本、标注记录、审核记录和争议处置；机器预标仅作待审输入。必填元数据必须完整，内容缺失或不可读字段标为 `null` 并附原因。

---

## 七、 group_key 切分与防泄漏

切分由 TrainPlatform 治理，ModelTrain 不得自行重切分。`group_key` 表示不可跨 split 的关联组：

1. 同一实物、采集会话、原图与其裁剪/缩放/增强衍生图、精确重复及近重复归入同组；
2. 若宣称跨商品、批次泛化，须把相应商品/批次作为隔离维度；
3. 同组只进入 train、val、test 之一；冻结前检查各集合无组交集，val 统一表示验证集；
4. 先分组切分，再生成裁剪、增强或缓存；派生图继承原组和 split，保留原样本、变换参数与标注坐标，不改原图、不增加独立样本计数；
5. 测试集不用于调参、阈值、字典、纠错权重、量化校准或模型选型。

冻结输入只读，派生产物写隔离输出；遮挡、旋转或增强后重新核对标签可见性和坐标，不能对不可见字符沿用完整 OCR 真值。新增近重复关系时复核受影响切分与版本。

---

## 八、 冻结审核与难例隔离

- **冻结版本**：绑定原图完整性摘要、标注规范与版本、来源许可记录、审核结论、group_key/split 映射及版本清单；冻结后只读；
- **训练资格**：在线纠偏在 InferPlatform 业务接受后立即重算，不等于训练合格。TrainPlatform 对授权、真值、标注质量与组关系独立审核；未审或拒绝不得进入训练冻结版本；
- **negative 隔离**：无目标但真实合规图像可作负样本，区分“无目标”与“存在但不可读”，独立标记并报告误检；
- **hardcase 隔离**：反光、遮挡、截断、粘连或干扰样本单独标记、分层和版本化；严禁删除难例以虚增指标；
- **用途隔离**：标准集、研究集与待审纠偏池分别管理，共享防泄漏分组约束。

---

## 九、 自动化门禁与人工复检

每次入库、标注、切分或冻结变更遵循先核验、后执行、再复检流程：

| 检查项         | 要求与限制                                                            |
| :------------- | :-------------------------------------------------------------------- |
| 清单与文件映射 | 稳定 ID 唯一，每条图像记录关联存在文件，声明范围内无遗漏或悬空        |
| SHA-256        | 验证文件完整性与精确重复，防止改名重复入库；非拍摄真实性证明          |
| pHash          | 提供近重复候选，人工复核同物/同源关系；不使用无依据的固定阈值放行     |
| 标注与类型     | bbox 合法、OCR 与语义来源一致，必填元数据合法，缺失和不可读显式记录   |
| 来源与冻结     | 许可覆盖用途、审核可追溯、group_key 无跨 split 泄漏、版本清单哈希一致 |

任何哈希结果均不能替代单张原图审阅。门禁失败先定位原因，严禁删改难例或补造字段以制造通过结果。
